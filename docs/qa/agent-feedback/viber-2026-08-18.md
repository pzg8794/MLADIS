## Feedback and disposition

| Feedback | Disposition | Reason |
|---|---|---|
| Separate operational response context from identity-free learning data. | Accepted | Operations must resolve the correct thread, guest, reservation, and property before drafting; learning records must not be used for identity lookup. |
| Remove private message text from CLI arguments. | Accepted | Shell history and process inspection can expose command-line values; the draft command now reads stdin or a protected file. |
| Do not accept arbitrary external session IDs. | Accepted | The workflow now generates an internal session ID for the draft command. |
| Strengthen low-stakes approval with property grounding and risk signals. | Accepted | A draft is not sendable unless its property context is resolved, no risk reason remains, and its mode is recognized. The sender is still not configured. |
| Add domain-to-persistence terminology and reconciliation boundaries. | Accepted | The behavior map now documents `Reservation -> BookingInquiry`, `Guest -> CustomerProfile`, property/work-order mappings, and explicit snapshot/identity resolution states. |
| Put Property/BookableItem in the center of the behavior graph. | Accepted | Rules, occupancy, visitors, availability, pricing, arrival, and listing state depend on property context. |
| Test a new message in an existing thread and changed captures. | Accepted | The checkpoint now fingerprints observations per collection and the regression suite proves unchanged captures skip while a later message is accepted once. |
| Add durable ResponseDraft/ResponseReview records before any live sender. | Deferred | There is no sender adapter in this preparation pass. This remains a gate before any customer-facing sender is implemented. |
| Make the repository private. | Deferred / owner action | Repository visibility is an account-level GitHub operation, not silently changed by this code follow-up. It remains a required privacy review for customer-adjacent work. |
| Add sender destination, stale-thread, approved-hash, and idempotency controls. | Deferred | Required before a live sender; no outbound Airbnb adapter is enabled. |
