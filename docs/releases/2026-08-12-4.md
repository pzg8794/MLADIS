## Scope

This release closes the gaps found by a controlled real-world reservation and
payment canary:

- preserve cent precision in stay and damage authorization records;
- show actual transaction-object totals in customer/admin confirmation documents;
- distinguish authorization from payment capture in customer-facing confirmation copy;
- reconcile Stripe PaymentIntent state into MLADIS;
- capture due stay-payment holds using an idempotent scheduled lifecycle service;
- release open stay and damage authorization holds after reservation cancellation;
- send lifecycle evidence to both the customer and MLADIS operations recipients;
- install a five-minute systemd timer for the lifecycle command.

No database migration, authentication change, PayPal change, or new refund/
adjustment object is included.

## Manual Verification

The production canary used one real customer account and one real manager
account. It verified:

- customer reservation creation and account visibility;
- manager Calendar, List, Rooms, Analytics, settings, block, and price-override workflows;
- customer denial from the staff-only operations calendar;
- a live Stripe manual authorization captured for exactly USD 0.99;
- a live Stripe refund for exactly USD 0.99;
- customer authorization email, MLADIS operations copy, Stripe payment receipt,
  and Stripe refund receipt in the controlled inbox;
- customer cancellation of the canary reservation;
- removal of the canceled reservation from the manager calendar.

The production database was audited before scheduler activation. The only
provider-linked open record was the already refunded, canceled USD 0.99 canary;
there were no due customer stay holds eligible for capture.

## Known Limitations

- PayPal remains unavailable until approved credentials are configured.
- Stripe provider/webhook delivery must be revalidated after deployment and
  secret rotation; that result belongs in the post-deployment report.
- The canary proves the tested reservation, calendar, email, capture, refund,
  and cancellation paths. It is not evidence for every external provider edge
  case or every future scheduled execution.

## Rollback

Rollback target: `release/2026.08.12-3`

```bash
git fetch --tags origin
git checkout release/2026.08.12-3
./deploy_mladis_vm.command
```

If rolling back, also disable the scheduler installed by this release:

```bash
sudo systemctl disable --now mladis-payment-lifecycle.timer
```

The deployment script creates a VM runtime backup before syncing code. Do not
overwrite the production `.env`, database, media, or virtual environment during
rollback.
