# Anonymous Interaction Lake Contract

## Purpose

`INTERACTIONS/anonymous_interactions.jsonl` is the identity-free learning
collection for MLADIS and approved source-system imports such as Airbnb host
messages. It stores conversation shape and response content so the team can
improve questions and answers without creating a second customer directory.

The Django database remains the source of truth for operational conversations.
The interaction lake is an analysis and learning copy, not a replacement for
customer, reservation, payment, or deposit records.

## Record Shape

Each JSONL row contains:

```json
{
  "schema_version": "1.0",
  "collection": "anonymous_interactions",
  "entity_type": "conversation_interaction",
  "record_key": "conversation:<random-id>",
  "source_system": "airbnb|mladis",
  "channel": "host_messages|booking_agent",
  "pii_classification": "anonymized",
  "occurred_at": "timestamp",
  "data": {
    "language": "en",
    "topic": "availability",
    "outcome": "",
    "turn_count": 2,
    "turns": [
      {"sequence": 0, "role": "guest", "text": "..."},
      {"sequence": 1, "role": "host", "text": "..."}
    ],
    "redaction": {
      "direct_identifiers_removed": true,
      "source_ids_removed": true,
      "participant_names_removed": true
    }
  }
}
```

`record_key` is generated by MLADIS and is not derived from a customer,
Airbnb, reservation, session, or account identifier.

## Redaction Rules

Before a row is written, the ingestion service removes or replaces:

- participant names supplied as source metadata,
- email addresses and phone numbers,
- URLs and thread links,
- booking, reservation, work-order, and long numeric references,
- common street-address patterns,
- self-introduced names and conservative capitalized name sequences.

Roles are reduced to `guest`, `host`, `agent`, `system`, or `unknown`. Source
IDs, usernames, account IDs, session IDs, direct contact fields, and raw source
metadata are not part of the record shape.

This is a learning dataset, not a promise that arbitrary free text can be
perfectly de-identified. The sanitizer is intentionally conservative; an
operator must review a source import before mirroring it to Drive. Never use
the lake for identity lookup or customer targeting.

## Sources and Ingestion

New MLADIS booking-agent conversations are captured by the application signal
through `AnonymousInteractionLakeWriter`. This write is append-only and must
never block a booking or agent response.

Airbnb exports are imported only through an explicit local command using a
private JSON/JSONL input file. The input is not committed to Git and is not
copied to the output folder. The preferred command routes both datasets in one
run:

```bash
cd airbnb_agent
python manage.py collect_airbnb_data_lake \
  --input /private/path/airbnb-combined-export.json
```

The focused interaction-only command remains available:

```bash
cd airbnb_agent
python manage.py ingest_anonymous_interactions \
  --input /private/path/airbnb-conversations.jsonl
```

To mirror the sanitized output to the configured Drive object-lake folder:

```bash
cd airbnb_agent
python manage.py ingest_anonymous_interactions \
  --input /private/path/airbnb-conversations.jsonl \
  --sync-drive
```

The combined input format and four-scope process are documented in the
[Airbnb collection runbook](airbnb-collection-runbook.md). The interaction
portion is a list of objects or JSONL rows with `turns`, and optional
`source_system`, `channel`, `language`, `topic`, `outcome`, and `known_names`.
The command reports counts and paths only; it must not print message contents.

## Retention and Access

- Runtime JSON/JSONL belongs in the protected Drive folder, not Git.
- Raw Airbnb exports remain local/private only and must be deleted according
  to the business retention policy after successful review and ingestion.
- The lake must not contain passwords, OAuth secrets, payment cards, identity
  documents, SSNs, bank records, customer names, email addresses, phone
  numbers, booking references, or thread URLs.
- A future learning pipeline may derive aggregate topics, tone, resolution,
  unanswered-question, and response-quality metrics, but must not reconstruct
  identities from the interaction rows.
